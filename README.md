# GEO-SHIELD

## Flood Disaster Exposure & Emergency Decision Intelligence

**Problem Statement:** Domain 4 — Disaster Risk Analysis  
**Selected problem:** 4.4 — Disaster Exposure Mapping

GEO-SHIELD is an interactive Potheri / SRM KTR prototype demonstrating spatial exposure analysis with the hazard and infrastructure data currently available in the repository. It retains the existing scenario dashboard, GIS map, resource optimizer, and evacuation-route views.

The current hazard representation is the **MODELED FLOOD SUSCEPTIBILITY** grid generated by GEO-SHIELD's backend risk model. It is a susceptibility heuristic, not an observed flood extent, satellite-detected event, or flood prediction. The exposure mask for reported infrastructure metrics consists of cells classified HIGH or CRITICAL for the selected scenario.

## Problem 4.4 workflow

```text
Available hazard geometry + available infrastructure geometry
    → spatial intersection
    → hazard-exposure map and affected-infrastructure statistics
```

The `/exposure` API computes road-length intersections from real-source OSM road centerlines and point-in-polygon tests for facilities with coordinates. Map popups indicate whether each analyzed road or facility intersects the modeled susceptibility mask. The map retains existing water bodies as context; they are not counted as affected assets.

## Exposure results and data limits

- **Roads:** total OSM line length, the portion intersecting HIGH / CRITICAL susceptibility cells, and the exposed percentage. These are computed geometrically, not from road-record counts. Both lengths are clipped to the partial OSM query extent so their percentage uses one consistent area. Only real-source OSM road features are included in these summary totals; demo road lines remain visible as context.
- **Facilities:** total mixed-source inventory, number of locations that could be tested, and number whose source coordinates intersect the modeled susceptibility mask. Inventory totals are kept separate from exposed counts. OSM coverage is partial and most facility records are demo fallbacks.
- **Buildings, settlements, and land use:** unavailable in the current study-area dataset; no counts or area estimates are fabricated.
- **Population:** not reported as observed or spatially measured exposure. The retained demo population proxy remains an internal input to the legacy resource-priority heuristic and is not shown as an exposure result.
- **Water bodies:** map context only; not included in affected-asset statistics.

The exposure definition is intentionally narrow and repeatable: a road segment is exposed where its line geometry overlaps a HIGH / CRITICAL susceptibility cell; a facility is exposed where its source point intersects one of those cell polygons. The map and panel label this as modeled susceptibility exposure, not observed flooding.

## Current datasets

Source metadata, retrieval times, coverage, and attribution are maintained in `backend/data/provenance.json` and served by `GET /data-sources`.

- **Elevation:** Copernicus DEM GLO-30, sampled at centroids of the 180 m risk grid. It is an elevation-derived susceptibility input, not water depth.
- **Roads and water:** partial OpenStreetMap snapshot. The retained snapshot includes road centerlines and water geometries for only part of the pilot area; it is not a complete or real-time inventory.
- **Facilities:** mixed inventory: two OSM university features plus retained demo facilities. See the API feature-level source labels.
- **Rainfall:** hypothetical scenario inputs, or a separate cached Open-Meteo model forecast where its validity window is current. Forecast rainfall is not observed rainfall, and the API selects either forecast or scenario input rather than combining them.
- **Population, drainage, and land-cover susceptibility factors:** inherited demo values. No gridded observed population or real land-cover product is integrated.
- **Buildings, settlements, agriculture/land use, and satellite flood extent:** not available in the current repository.

The backend risk score remains a prototype susceptibility heuristic:

```text
rainfall_risk = clamp(0, 100, ((rainfall_mm - 40) / 140) * 80 + 18)
adjusted_drainage = min(100, drainage_factor * (1 + (rainfall_mm - 40) / 300))
risk_score = 0.30 * elevation_factor
           + 0.25 * rainfall_risk
           + 0.20 * adjusted_drainage
           + 0.15 * landcover_factor
           + 0.10 * water_proximity_factor
```

The weights have not been calibrated against historical flood observations. Scores classify cells into LOW (≤25), MODERATE (≤50), HIGH (≤75), or CRITICAL (>75). This classification is the prototype's susceptibility scale, not an operational flood warning.

## Application architecture

- **Frontend:** React 18, Vite, Tailwind CSS, React-Leaflet, and Recharts.
- **Backend:** FastAPI. The backend evaluates the risk grid, exposes provenance and spatial exposure metrics, and provides optimizer, infrastructure, rainfall, and route APIs.
- **Data:** compact local JSON / GeoJSON products under `backend/data/`. One-time ingestion scripts are in `backend/`; API requests do not fetch external datasets.
- **Map base tiles:** CARTO Dark Matter when `VITE_CARTO_API_KEY` is configured, otherwise OpenStreetMap tiles.

### API endpoints

- `GET /health` — service and study-area status.
- `GET /methodology`, `GET /data-sources`, `GET /study-area` — model, provenance, and area metadata.
- `GET /rainfall` — active rainfall selection and cached forecast provenance.
- `GET /risk-zones`, `GET /risk-summary`, `POST /simulate` — modeled susceptibility and scenario outputs.
- `GET /exposure?rainfall=120&rainfall_mode=scenario` — spatial roads/facilities exposure summary.
- `GET /infrastructure`, `GET /resources`, `POST /optimize` — map features, inventory, and heuristic recommendations.
- `GET /routes/scenarios`, `GET /routes?scenario_id=EVAC-01` — modeled route scenarios; uses the available OSM road graph when routable, otherwise an explicitly labeled fallback.

## Run locally

### Backend

```bash
cd backend
python -m pip install -r requirements.txt
python -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

API documentation is available at `http://127.0.0.1:8000/docs`.

Run backend tests:

```bash
python -m unittest discover -s tests -v
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Copy `.env.example` to `.env` to configure `VITE_API_BASE_URL` and optionally `VITE_CARTO_API_KEY`.

## Prototype limitations

This project is a demonstrator, not an operational flood-monitoring or dispatch system. It has no observed flood mask, buildings or settlement layer, observed gridded population, or land-use layer. OSM coverage is partial; several factors and facilities are demo data. The susceptibility model is not a calibrated hydrological model, and route output is not live navigation, traffic, or a flood-safety guarantee. Results should be interpreted with the data provenance and limitations shown in the application.
